# Point Cloud Mamba on PSNet5

This repository contains an adaptation of Point Cloud Mamba (PCM) for five-class semantic segmentation of industrial point clouds in PSNet5, together with dataset analysis, development experiments, evaluation outputs, and figures. The original implementations are [Point Cloud Mamba](https://github.com/zhang-tao-whu/PCM) and [ResPointNet++ / PSNet5](https://github.com/PointCloudYC/ResPointNet2). Our working repositories are [PCM](https://github.com/trampo-tech/PointCloudMamba_on_PSNet5.git) and [ResPointNet++](https://github.com/trampo-tech/respointnet_compute_proof).

## Artifact inventory

Paths are relative to this repository unless stated otherwise.

- `examples/segmentation/main.py`: training and validation entry point. `--cfg` selects the model configuration; the run directory under `log/psnet5/` receives resolved configurations, logs, metrics, and checkpoints.
- `openpoints/models/PCM/`, `openpoints/models/segmentation/`, and `openpoints/cpp/`: model implementation and required native operators.
- `openpoints/dataset/psnet5/`: PSNet5 preprocessing, sphere sampling, and voting implementation.
- `cfgs/psnet5/default.yaml` and `cfgs/psnet5/PCM-ce-weighted.yaml`: dataset, optimization and model settings for the weighted cross-entropy experiment. `PCM-ce-classmix.yaml` specifies the class-aware sampling experiment; `PCM-ce-nosmoothing.yaml` describes an incomplete experiment, not a completed result. `cfgs/psnet5/README.md` gives further protocol details.
- `analysis/psnet5/split.json` and `analysis/psnet5/results/Area_{1,2,4}_partition.npz`: development split and partition masks. `analysis/psnet5/reports/REPORT.md` describes the data and split.
- `analysis/psnet5/evaluate_multivote.py`: evaluation of a supplied checkpoint. `--cfg` selects its model settings, `--checkpoint` the weights, `--benchmark-area3` the Area 3 evaluation, `--votes` the number of voting passes, `--num-steps` the spheres per pass, `--seed` the evaluation seed, and `--output` the results directory.
- `analysis/psnet5/results/weighted_ce_epoch39_area3/`: recorded Area 3 summary, per-class metrics, confusion matrix, vote metrics and prediction export for the weighted run. `analysis/psnet5/weighted_ce_40_report/` contains its report and figures. The matched baseline is in `analysis/psnet5/batchnorm_40_report/` and `analysis/psnet5/results/batchnorm_40_fixed_eval_area3/`.
- `analysis/psnet5/results/classmix_epoch35_area3/` and `analysis/psnet5/results/weighted_ce_60_smoothing01_area3/`: Area 3 results for the class-mix and 60-epoch weighted experiments. The directories `analysis/psnet5/results/classmix_40_training/`, `analysis/psnet5/results/classmix_error_analysis/`, `analysis/psnet5/results/classmix_spatial_analysis/`, `analysis/psnet5/results/height_sensitivity_dev/`, and `analysis/psnet5/results/training_exposure_analysis/` contain training summaries and supporting investigations.
- `log/psnet5/psnet5-train-PCM-ngpus1-20261005-173320-fEPnR2XCrEZgTem26LBB9e/` and `log/psnet5/psnet5-train-PCM-ce-weighted-ngpus1-20261014-013255-RYxnShfJR67zVkme9fdFat/`: original training logs for the unweighted baseline and weighted experiment, respectively.
- `analysis/psnet5/reports/CURRENT_FINDINGS.md`, `analysis/psnet5/reports/PADDING_INVESTIGATION.md`, and `analysis/psnet5/reports/REFERENCE_EVALUATION_AUDIT.md`: findings and limitations, padding investigation, and evaluation protocol audit. Other subdirectories under `analysis/psnet5/results/` contain class-mix, sensitivity, exposure and earlier diagnostic results; analysis scripts are under `analysis/psnet5/`.
- `analysis/psnet5/dataset/`, `analysis/psnet5/diagnostics/`, and `analysis/psnet5/investigations/`: dataset audit and split scripts, padding checks, and scripts for the height, exposure, and spatial-error analyses.
- `analysis/psnet5/make_paper_figures.py` and `analysis/psnet5/paper_figures/`: figure-generation script and the resulting PNG and PDF figures.
- `Dockerfile` and `requirements.txt`: environment and installation resources. `tests/` contains implementation checks.

PSNet5 data, processed caches, and trained checkpoints are not included in this repository. The two logs listed above are included; other run directories, logs, caches, and checkpoints are generated by a new execution and are not part of the delivered files.

## Recorded best result

The weighted experiment trained for 40 epochs with seed `20261004`, batch size 2, 15,000 points per sphere, radius 2 m, 0.04 m voxel size, masked cross-entropy, label smoothing 0.2, and class weights computed from training-partition frequencies as `1 / (frequency + 0.02)`, normalized to mean 1. The selected checkpoint was epoch 39, with development mIoU 86.08%. The separate Area 3 evaluation used one vote, 2,000 spheres and current-sphere BatchNorm statistics, reporting 69.23% mIoU, 85.08% overall accuracy and 100% raw-point coverage. See the report and `summary.json` above for per-class results.

Training and development validation used spatial partitions of Areas 1, 2 and 4. This is a single-seed comparison. Area 3 was used for exploratory evaluation during development, so it is not an untouched test set. Retraining follows the recorded workflow but can produce different results.

## Reproduce the workflow

The PCM Dockerfile uses PyTorch 2.1.2, CUDA 11.8 and cuDNN 8. Building requires Docker BuildKit and downloads dependencies. Running requires an NVIDIA GPU and Docker GPU support. ResPointNet++ preprocessing uses its own Conda environment.

1. Clone [our ResPointNet++ repository](https://github.com/trampo-tech/respointnet_compute_proof), download PSNet5 using its dataset instructions, and extract it under `ResPointNet2/data/PSNet/PSNet5/`. The directory should contain `Area_1/` through `Area_4/`, with `Room_*/Annotations/*.txt` files. Follow that repository's Conda installation instructions to create the `respointnet2` environment and compile its operators. Then preprocess the data from the ResPointNet++ repository directory:

```bash
conda activate respointnet2
python datasets/PSNet5.py
```

This creates `processed/Area_N.pkl` and `processed/Area_N_0.040_sub.pkl` files. The preprocessing command also generates ResPointNet++ sampling and projection caches and can take substantial time and disk space.

2. From this PCM repository, build the image and create fresh writable directories for this run. Replace the example run directory if it already contains an earlier processed PCM cache.

```bash
docker build -t pcm-psnet5 .
mkdir -p psnet5-run/data psnet5-run/log psnet5-run/output
```

3. Replace `/absolute/path/to/ResPointNet2/data/PSNet/PSNet5` with the preprocessed PSNet5 directory and start the container:

```bash
docker run -it --gpus all --ipc=host --shm-size=16g \
  -v /absolute/path/to/ResPointNet2/data/PSNet/PSNet5:/workspace/ResPointNet2/data/PSNet/PSNet5:ro \
  -v "$PWD/psnet5-run/data:/workspace/PointCloudMamba/data/PSNet5" \
  -v "$PWD/psnet5-run/log:/workspace/PointCloudMamba/log/psnet5" \
  -v "$PWD/psnet5-run/output:/workspace/PointCloudMamba/output/psnet5" \
  pcm-psnet5
```

4. Inside the container, generate masks using the spatial boundaries in `analysis/psnet5/split.json`, then run the weighted training:

```bash
python analysis/psnet5/dataset/finalize_split.py \
  --data-root /workspace/ResPointNet2/data/PSNet/PSNet5
python examples/segmentation/main.py --cfg cfgs/psnet5/PCM-ce-weighted.yaml
```

The split script writes masks and associated hashes to `analysis/psnet5/results/` inside the container; this directory is not mounted. Restart the same container to reuse its masks, which disappear if the container is removed. The masks correspond to the newly preprocessed data. Running the split script directly in a repository checkout overwrites the tracked partition masks and split outputs. Use a fresh PCM cache when preparing data again; existing PCM caches can otherwise be reused.

The selected `*_ckpt_best.pth` is written under `log/psnet5/<run>/checkpoint/`, which is mounted to `psnet5-run/log` on the host. To evaluate it on Area 3, substitute its path inside the container:

```bash
python analysis/psnet5/evaluate_multivote.py \
  --cfg cfgs/psnet5/PCM-ce-weighted.yaml \
  --checkpoint /path/to/ckpt_best.pth \
  --benchmark-area3 --votes 1 --num-steps 2000 --seed 20261004 \
  --output output/psnet5/weighted-area3
```

The evaluator writes `summary.json`, per-class and vote metrics, confusion matrices, and per-area prediction exports to `--output`, mounted to `psnet5-run/output` on the host. Current-sphere BatchNorm is enabled by the default configuration. The output from a newly trained checkpoint is a new run, not the original saved result. See `cfgs/psnet5/README.md` for coverage and evaluation details.
